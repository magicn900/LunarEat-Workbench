# 工作台

一个自托管的 Web 游戏策划协作平台。通过浏览器整理文档、管理结构化数据，并让 coding agent 与你共同编辑同一份草稿。

项目名称为 LunarEat-Workbench。当前处于开发阶段，适合本地体验和团队试用，尚未经生产环境安全审计。

## 可以做什么

- **编写和组织文档**：Markdown 编辑、页面目录、双向链接、文档嵌入、搜索，以及工具栏和斜杠快捷插入。
- **管理自定义数据**：自行定义集合与字段，通过表格、列表或卡片查看和编辑；支持筛选、排序和分页。视图可以嵌入文档，始终编辑同一份数据，不硬编码游戏实体。
- **与 Agent 一起编辑**：每个账号有独立草稿，Agent 使用该账号授权的权限读写；修改实时显示在浏览器中，支持撤销，人工可以随时收回控制权。
- **发布团队设计**：检查修改、丢弃无意改动，再发布到团队正式版本。不需要额外审批流程。
- **跟踪实现同步**：程序员或获授权 Agent 可以将发布记录标记为“已确认同步至实现”，并记录对应的代码提交；工作台不自动验证外部代码。
- **收集共享灵感**：便签独立于设计版本，由项目成员共享；Agent 通过独立入口访问。

界面提供浅色、深色和系统主题，支持简体中文与 English。账号、项目和权限通过管理页面维护。

## 快速体验

需要 Node.js 24、pnpm 11 和 Git。在项目目录运行：

```sh
pnpm install --frozen-lockfile
pnpm seed
pnpm build
pnpm start
```

浏览器打开 http://127.0.0.1:14311 。初始化会输出 designer 和 developer 两个示例账号的随机密码，请妥善保存；这只是两个权限不同的普通账号，不是固定用户类型。

示例包含虚构的策划文档、技能集合和共享便签。可以从“战斗概览”开始，编辑嵌入表格，再进入集合查看同一份数据；整理好草稿后点击“发布变更”。

数据默认保存在 .local-data/demo，不会写入游戏代码仓库。初始化仅用于空数据目录，不要在已有数据上反复执行 seed。

## 接入 Agent

登录后点击侧栏账号条 → 设置 → Agent 接入，复制安装指令交给 Agent，并创建所需权限的凭据。

工作台通过 Skill 和远程 API 提供协作能力，不内置模型，也不要求 Agent 克隆本项目或安装服务端依赖。凭据通过私有环境变量提供，不要贴进聊天或提交到源码仓库。远程连接需要 HTTPS。

## 开发

前端使用 React 和 Milkdown，服务端使用 Node.js。内容以 Markdown / YAML / JSON 文本对象保存，SQLite 管理账号和工作状态，Git 记录正式设计版本。

运行 pnpm dev 启动开发环境，浏览器入口为 http://127.0.0.1:15173，默认 API 端口为 14311。构建命令为 pnpm build，自动测试为 pnpm test；浏览器测试运行 pnpm exec playwright install chromium 后执行 pnpm build 和 pnpm test:e2e。

项目目前面向单实例在线部署，不支持离线编辑、多实例集群或跨账号共同编辑一份个人草稿。开发期不保证历史数据格式兼容，更新前请备份。
